# 受控扫描与报告案例

本案例只扫描脚本新建的合成目录。分析 JSON 是根据生成记录编写的固定案例解释，**不是自动分类器，也不是真实用户清理效果**。不读取个人目录、不调用 DISM、不提权、不修改 ACL。

在仓库根目录运行（目标目录必须不存在）：

```text
python scripts/demo_case.py work/demo-001
python scripts/build_report.py work/demo-001/analysis.json work/demo-001/rebuilt.html
```

输出包括 `synthetic-files/`、`scan.json`、`analysis.json` 和静态只读 `report.html`。同一目标再次运行会拒绝覆盖；复跑使用新的目录名。不要提交生成目录（其中含本机绝对路径）。

样本包含三个已知可丢弃文本、普通合成文档、空目录、中文/空格/`&` 路径，以及一个通过受控 `scandir` 异常模拟的权限失败目录。未修改真实权限。扫描应得到 4 个已读取文件、1 次读取失败，失败目录为 `partial`；不是空目录。分析保留原始覆盖信息，不给合成个人资料设置删除路径。所有大小是逻辑文件长度，不测量物理占用或净释放量。

交互验收使用新目录，且目标需位于当前 HOME 内（沿用真实服务的路径边界）：

```text
python scripts/demo_case.py work/demo-002 --serve
```

打开终端打印或 `work/demo-002/demo-url.txt` 中的本地地址。按 Ctrl+C 结束服务。

1. 展开“查看扫描目标与遗漏依据”，核对模拟读取失败的路径、错误和口径；展开黄色卡片核对依据与处理步骤。
2. 点击“全部移回收站”，核对页内确认框列出全部精确路径、目录递归影响和空间说明；默认焦点在“取消”。先取消：应显示“已取消，未发送操作”，样本保持原样。
3. 再次点击并确认：01 样本仅重命名到本案例 `simulated-trash/`（可移回），02 返回模拟取消，03 尚未执行。页面应只将 01 标为已处理，02 / 03 保留操作入口；批量结果不宣称全部成功。
4. 单独操作 03，返回模拟文件锁定失败，原文件保留。单独操作 02，返回模拟取消，原文件保留。
5. 对任一剩余目标打开确认框，按 Escape：应取消且不发送请求，焦点回到发起按钮。窄屏下目标路径完整换行、确认和取消按钮均可见。
6. 黄色卡片的“打开”调用正常文件管理器，页面只显示请求已提交；不会标为清理完成。静态报告没有删除按钮。

**交互演示没有调用系统回收站。** “直接删除”在演示服务中被禁用并返回错误。不要把此服务的模拟结果当作系统回收站验收。真实直接删除仅在回归测试自己的临时目录内执行。

回归检查：

```text
python -m unittest discover -s scripts -p "test_*.py" -v
```

测试覆盖逻辑大小、读取失败与文件消失、列表过滤、跳过链接、根目录拒绝、逐路径成功/取消/失败/未执行、重叠批次拒绝和报告嵌入。存在 Node 时，还会运行真实报告函数的最小 DOM 适配器测试（包括部分完成后保留目标），这属于模拟状态检查，不能代替浏览器视觉验收。同时检查确认、取消、不支持对话框时默认拒绝、路径转义和已知容量布局。没有 Node 时仅跳过这一可选检查，不安装依赖。

当前局限：macOS 的 `du` 扫描尚无与 Windows 等价的覆盖诊断；旧 analysis JSON 缺 `coverage` 或 `evidence` 时报告会提示未知，而不会替其编造。报告中的磁盘容量、分级和建议体量是扫描快照，操作后不会自动重算。目录操作中途失败可能已影响部分子项，服务返回的是目标路径级结果，不是完整子文件审计。
